¿Qué es una prueba y para qué sirve?

Primero entiende el por qué antes de ver código.

🍕
Piénsalo así
Imagina que tienes una receta para hacer pizza. Cada vez que la sigues, ¿cómo sabes que el resultado fue correcto?
Las pruebas hacen lo mismo con tu código: comprueban automáticamente que una función hace lo que debe hacer.

🔴 Sin pruebas

Cambias una línea de código, abres el navegador, escribes números a mano y ves si el resultado se ve bien. Lento y te puedes equivocar.

🟢 Con pruebas (Jest)

Escribes los casos una sola vez. Luego, con un solo comando, Jest verifica en segundos que todo funciona bien.

En resumen
Una prueba es un pequeño programa que llama a tu función con valores conocidos y comprueba que el resultado sea el correcto.

¿Qué necesitas para empezar?

Solo dos archivos y un comando de instalación.

Estos son los archivos del proyecto:

📄 math.js

Tu código real: las funciones sumar() y restar() que queremos probar.

🧪 math.test.js

El archivo de pruebas. Jest lo detecta automáticamente porque termina en .test.js.

$ npm install --save-dev jest
# Esto descarga Jest y lo guarda en package.json

⚙️ Revisa tu package.json:

📄 package.jsonJSON
{
  "scripts": {
    "test": "jest"    // ← Este es el comando que ejecuta las pruebas
  },
  "devDependencies": {
    "jest": "^29.7.0"  // ← Jest instalado como herramienta de desarrollo
  }
}

¿Por qué devDependencies?
Jest es solo para desarrolladores. Los usuarios de tu app no lo necesitan, por eso va en devDependencies (dependencias de desarrollo).
3

El código que vamos a probar

Antes de escribir pruebas, entiende bien qué hace el código.

Este es el archivo math.js con comentarios explicados línea por línea:

📄 math.js — explicadoJS
// 1️⃣ Definimos la función sumar con dos parámetros: a y b
function sumar(a, b) {

  // 2️⃣ Number() convierte el valor a número
  //    Ejemplo: Number("5") → 5   |   Number("hola") → NaN
  const numA = Number(a);
  const numB = Number(b);

  // 3️⃣ isNaN() detecta si la conversión falló (NaN = "Not a Number")
  if (isNaN(numA) || isNaN(numB)) {
    // 4️⃣ Si no son números, lanzamos un error con un mensaje claro
    throw new Error("Entrada inválida: deben ser números.");
  }

  // 5️⃣ Si todo está bien, devolvemos la suma
  return numA + numB;
}

// La función restar() funciona igual, pero con resta
function restar(a, b) {
  const numA = Number(a);
  const numB = Number(b);
  if (isNaN(numA) || isNaN(numB)) {
    throw new Error("Entrada inválida: deben ser números.");
  }
  return numA - numB;
}

// 6️⃣ Exportamos las funciones para que math.test.js pueda usarlas
module.exports = { sumar, restar };
✅
Lo importante
sumar(5, 3) debe devolver 8.
sumar("hola", 2) debe lanzar un error.
Nuestras pruebas verificarán exactamente esto.
4

Tu primera prueba, explicada línea por línea

Una prueba tiene solo tres partes. Veámoslas una por una.

🔤
Primero: importa las funciones
Al inicio del archivo math.test.js, necesitas traer las funciones de math.js:
const { sumar, restar } = require('./math');

Ahora veamos una prueba completa:

// ─────────────────────────────────────────────────────
// PARTE 1: El nombre de la prueba (aparece en la consola)
// ─────────────────────────────────────────────────────
test('S1: Suma de dos números positivos', () => {
  //   ↑ Texto descriptivo: di QUÉ se está probando

  // ─────────────────────────────────────────────────
  // PARTE 2: Llamamos a la función con valores conocidos
  // ─────────────────────────────────────────────────
  const resultado = sumar(6, 3);
  //                       ↑  ↑ Entradas que nosotros controlamos

  // ─────────────────────────────────────────────────
  // PARTE 3: Verificamos que el resultado es el correcto
  // ─────────────────────────────────────────────────
  expect(resultado).toBe(9);
  //  ↑ "Espero que..."  ↑ "...sea igual a 9"

});
// Si llega aquí sin error → ✅ Prueba PASADA
// Si .toBe() detecta algo distinto → ❌ Prueba FALLIDA

📝 test('nombre', () => { })

El primer argumento es el nombre. El segundo es una función flecha () => {} que contiene la prueba. Si la función no lanza errores, la prueba pasa.

🔍 expect(valor).toBe(esperado)

Es como decir: "Espero que resultado sea exactamente 9". Si no coincide, Jest lo reporta como fallo.

5

Organiza tus pruebas con describe()

Cuando tienes muchas pruebas, describe() las agrupa para que el reporte sea más claro.

📁
Piénsalo como carpetas
describe() es como una carpeta que agrupa pruebas relacionadas.
test() es el archivo dentro de la carpeta, donde está la prueba real.
📄 math.test.js — estructura completaJS
const { sumar, restar } = require('./math');

// 📦 describe PADRE: agrupa toda la suite de pruebas
describe('Operaciones Matemáticas Básicas', () => {

  // 📂 describe HIJO: agrupa solo las pruebas de sumar()
  describe('Función sumar()', () => {

    test('S1: Suma de dos números positivos', () => {
      expect(sumar(6, 3)).toBe(9);    // 6 + 3 = 9 ✓
    });

    test('S2: Suma con el cero', () => {
      expect(sumar(8, 0)).toBe(8);    // 8 + 0 = 8 ✓
    });

  }); // ← fin de describe('Función sumar()')

  // 📂 describe HIJO: agrupa solo las pruebas de restar()
  describe('Función restar()', () => {

    test('R1: Resta normal', () => {
      expect(restar(10, 4)).toBe(6);  // 10 - 4 = 6 ✓
    });

  }); // ← fin de describe('Función restar()')

}); // ← fin de describe PADRE
✅
Regla fácil de recordar
describe() → organiza (como una carpeta).
test() → verifica (hace la comprobación real).
Un describe() puede tener varios test() adentro.
6

Los comparadores (matchers) que más usarás

expect(resultado).comparador(valorEsperado) — hay uno para cada situación.

Comparador¿Para qué sirve?Ejemplo
.toBe(valor) Comprueba que el resultado es exactamente igual. Úsalo para números y textos simples. expect(sumar(6,3)).toBe(9)
.toBeCloseTo(n) Para decimales. En JS, 0.1 + 0.2 no es exactamente 0.3, por eso usamos este. expect(sumar(0.1,0.2)).toBeCloseTo(0.3)
.toThrow() Comprueba que la función lanzó un error. Úsalo siempre envuelto en () =>. expect(() => sumar("hola",2)).toThrow()
.toEqual(obj) Compara objetos o arrays campo por campo. expect({a:1}).toEqual({a:1})
⚠️
El caso especial de los decimales
Si escribes 0.1 + 0.2 en la consola de JavaScript verás:
0.30000000000000004
Por eso nunca uses .toBe(0.3) con decimales. Usa .toBeCloseTo(0.3).

¿Cómo probar que un error se lanza?

📄 math.test.js — probar erroresJS
// ❌ INCORRECTO — Jest no puede capturar el error así:
expect(sumar("hola", 2)).toThrow();

// ✅ CORRECTO — envuelve la función en () => para que Jest capture el error:
expect(() => sumar("hola", 2)).toThrow();
//          ↑ La función flecha "envuelve" la llamada para atrapar el error

📕 Resultado cuando algo falla (Jest te dice exactamente qué falló):

FAIL math.test.js
● Función sumar() › S1: Suma de dos números positivos
 
expect(received).toBe(expected)
Expected: 9 ← Lo que esperabas

✅ PASS (verde)

Todas las pruebas del archivo pasaron. El símbolo ✓ aparece junto a cada prueba que pasó.

❌ FAIL (rojo)

Al menos una falló. Jest muestra el valor esperado vs el valor recibido, y la línea exacta del error.

👀
Modo automático — re-ejecuta al guardar
Si quieres que Jest ejecute las pruebas automáticamente cada vez que guardes un archivo, usa:
npx jest --watch
