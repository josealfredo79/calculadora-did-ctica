¿Qué es una prueba y para qué sirve?

El fundamento conceptual antes de ver código.

🔴 Sin pruebas

Cambias una línea de código, abres el navegador, ingresas valores manualmente y cruzas los dedos. Cada cambio se convierte en una sesión de prueba manual que tarda minutos.

🟢 Con pruebas

Escribes el caso de uso una sola vez. Después, con un comando, Jest verifica en milisegundos que todo sigue funcionando correctamente, cada vez que cambias el código.

Definición Una prueba unitaria verifica que una unidad pequeña de código (una función) produce el resultado correcto para una entrada específica, de forma aislada y repetible.
2

Anatomía de una prueba

Cada prueba tiene exactamente tres partes: preparar, actuar y verificar.

// ① PREPARAR — ¿Qué datos vamos a usar?
// ② ACTUAR   — ¿Qué función llamamos?
// ③ VERIFICAR — ¿El resultado es el esperado?

test('S1: Suma de dos números positivos', () => {

    const resultado = sumar(5, 3);          // ② Actuar

    expect(resultado).toBe(8);               // ③ Verificar

});

📝 El nombre del test

La cadena 'S1: Suma de dos números positivos' es la descripción legible por humanos. Cuando algo falla, este texto aparece en la consola para identificar exactamente qué falló.

⚙️ La función flecha

El segundo argumento () => { } contiene el código de la prueba. Jest ejecuta esta función y si no lanza ninguna excepción, la prueba pasa.

3

describe() y test(): organización

Cómo agrupar pruebas relacionadas para que los reportes sean legibles.

📄 math.test.js JS 
describe('Operaciones Matemáticas Básicas', () => {
  // 📦 Bloque PADRE — agrupa toda la suite

  describe('Función sumar()', () => {
    // 📦 Bloque HIJO — agrupa los tests de sumar()

    test('S1: Suma de dos números positivos', () => {
      expect(sumar(5, 3)).toBe(8);
    });

    test('S2: Suma con el cero', () => {
      expect(sumar(7, 0)).toBe(7);
    });
  });

  describe('Función restar()', () => {
    // 📦 Bloque HIJO — agrupa los tests de restar()

    test('R1: Resta normal (a > b)', () => {
      expect(restar(10, 4)).toBe(6);
    });
  });
});
✅
Regla de oro describe() es para organizar. test() es para verificar. Un describe puede contener otros describe anidados y múltiples test.
4

Los Matchers: el lenguaje de las afirmaciones

expect(valor).matcher() — Los matchers son el corazón de cada prueba.

Matcher ¿Cuándo usarlo? Ejemplo en el proyecto
.toBe(valor) Igualdad estricta (===). Para números y strings simples. expect(sumar(5,3)).toBe(8)
.toBeCloseTo(n) Números decimales con posibles errores de punto flotante. expect(sumar(0.1,0.2)).toBeCloseTo(0.3)
.toThrow() Verificar que una función lanza una excepción. expect(() => sumar("hola",2)).toThrow()
.toEqual(obj) Igualdad profunda para objetos y arrays. expect({a:1}).toEqual({a:1})
.toBeTruthy() El valor es verdadero (no importa cuál exactamente). expect(resultado).toBeTruthy()
.toBeNull() El valor es exactamente null. expect(obtenerUsuario()).toBeNull()
.toContain(item) Un array o string contiene un elemento. expect(['a','b']).toContain('a')
⚠️
¡Cuidado con .toBe() y decimales! En JavaScript, 0.1 + 0.2 === 0.30000000000000004 por cómo funciona el punto flotante IEEE 754. Por eso el test S4 usa .toBeCloseTo(0.3) en vez de .toBe(0.3).

Probar que los errores se lanzan correctamente

Tan importante como probar el camino feliz es probar los casos de error.

📄 math.test.js — Test de error JS 
test('Manejo de errores: Si se envía texto no numérico, debe arrojar un error', () => {

  expect(() => sumar("hola", 2)).toThrow();
  //     ↑ función envuelta  ↑ matcher especial

});
🔴
Regla crítica: envuelve en una función flecha Si escribes expect(sumar("hola", 2)).toThrow() sin la función flecha, Jest no puede capturar la excepción y la prueba fallará con un error inesperado. Siempre usa expect(() => funcionQueDebeFallar()).toThrow().
📄 math.js — Por qué se lanza el error JS 
function sumar(a, b) {
  const numA = Number(a);
  const numB = Number(b);

  // Number("hola") → NaN
  if (isNaN(numA) || isNaN(numB)) {
    throw new Error("Entrada inválida: deben ser números.");
    //  ↑ Esto es lo que .toThrow() espera
  }

  return numA + numB;
}
6

Ejecutar Jest desde la terminal

Los comandos que necesitas conocer para el día a día.

▶️ Ejecutar todas las pruebas

$ npm test

👀 Modo vigilancia (watch)

$ npx jest --watch

Re-ejecuta automáticamente al guardar un archivo.

📄 package.json — Script configurado JSON 
{
  "scripts": {
    "test": "jest"   // npm test ejecuta este comando
  },
  "devDependencies": {
    "jest": "^29.7.0"
  }
}
💡
¿Por qué devDependencies? Jest es una herramienta de desarrollo. No se necesita en producción (cuando el usuario abre la app), solo para que los desarrolladores validen el código. Por eso va en devDependencies, no en dependencies.

✅ Qué significa PASS

El archivo de pruebas se ejecutó y todos sus tests pasaron. El ícono ✓ confirma cada test individualmente.

❌ Qué significa FAIL

Al menos un test falló. Jest muestra el nombre del test, el valor esperado (Expected) y el valor recibido (Received), y la línea exacta del error.

Cuestionario de verificación

Pon a prueba lo que aprendiste. Haz clic en la respuesta correcta.

Pregunta 1 de 4

¿Por qué el test S4 usa .toBeCloseTo(0.3) en vez de .toBe(0.3)?

A Porque .toBeCloseTo() es más rápido de ejecutar.
B Porque los números decimales en JavaScript tienen imprecisión de punto flotante y 0.1 + 0.2 no es exactamente 0.3.
C Porque .toBe() no funciona con números.

Pregunta 2 de 4

¿Qué sucede si en un test de error escribes expect(sumar("hola", 2)).toThrow() sin la función flecha?

A La prueba pasa igualmente porque Jest detecta la excepción automáticamente.
B La prueba muestra una advertencia pero continúa.
C Jest no puede capturar la excepción; la prueba termina con un error no controlado antes de que .toThrow() pueda verificarla.

Pregunta 3 de 4

¿Cuál es la diferencia principal entre describe() y test()?

A describe() organiza y agrupa tests relacionados; test() contiene el código que hace la verificación real.
B describe() ejecuta el código y test() lo describe con un nombre.
C Son sinónimos; se pueden usar indistintamente.

Pregunta 4 de 4

¿Por qué Jest está en devDependencies y no en dependencies?

A Porque Jest no es compatible con la versión de Node.js en producción.
B Porque es una herramienta de desarrollo y no se necesita para que la aplicación funcione para los usuarios finales.
C Porque devDependencies se instala más rápido.
